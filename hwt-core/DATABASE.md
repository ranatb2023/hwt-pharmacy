# DATABASE — master structure

Everything the system stores, in one place: what exists today, and what each phase adds.
Diagrams of the same thing are in [ERD.md](ERD.md).

- **Engine:** SQLite (better-sqlite3), single file at `backend/data/hms.db`, WAL mode.
- **Schema source:** `backend/src/schema.sql` (tables) + `backend/src/db.js` `migrate()`
  (idempotent `ALTER TABLE ADD COLUMN` for databases created before a column existed).
- **Adding a column?** Put the `CREATE TABLE` shape in `schema.sql` *and* an `add()` line in
  `migrate()`, so a fresh install and an existing one end up identical.

Status key — 🟩 **shipped** (in production today) · 🟦 **planned**, with the phase that adds it.

## 1. Conventions

| Convention | Rule |
|---|---|
| Primary keys | `id INTEGER PRIMARY KEY AUTOINCREMENT` on every table |
| Timestamps | `created_at TEXT NOT NULL DEFAULT (datetime('now'))` — **stored in UTC** |
| Business day | UTC + `settings.tz_offset_hours` (default 5). Use `backend/src/businessDay.js`, never raw `date(created_at)` |
| Booleans | `INTEGER NOT NULL DEFAULT 0/1` — SQLite has no boolean type |
| Money | `REAL`, rounded to 2 dp at the edge by `packaging.round2()` / `billingRules.round()` |
| Human-facing codes | Generated by `nextSeq(name)` from the `counters` table, inside a transaction |
| Foreign keys | `PRAGMA foreign_keys = ON` is set at connection time |
| Enumerations | Stored as `TEXT`, validated in the route layer, documented below |

### Invariants that new tables must respect

1. **Quantities are base units.** `stock_batches.quantity`, `bill_items.quantity` and
   `stock_movements.quantity` are all in the smallest sellable unit — one tablet, one
   capsule, one bottle. Strips and boxes exist only in `backend/src/packaging.js` and at
   the counter, which converts exactly once, at the edge.
2. **Prices are per base unit.** `products.sale_price`, `products.mrp`,
   `stock_batches.cost_price`, `stock_batches.mrp`. Strip and box prices are derived by
   multiplication. **Never add a per-strip or per-box price column** — two stored prices
   drift the first time one is edited.
3. **`products.pack_size` is derived** (`units_per_strip * strips_per_box`) and recomputed
   on every start-up. Never write it directly.
4. **Waived money is recorded, not discounted away** — it lands in `bills.subsidy`.
5. **Append-only tables are never updated or deleted from:** `audit_log`,
   `controlled_register`, `stock_movements`, and from Phase 04 `ledger_entries`.

## 3. Planned tables, by phase

Full DDL, endpoints and screens are in each phase file. This is the schema summary.

### Phase 01 — counter & catalogue

```sql
-- Managed dosage-form list; replaces the free-text products.form
CREATE TABLE product_types (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  name              TEXT NOT NULL UNIQUE,       -- Tablet, Capsule, Syrup, Injection, IV set...
  is_medicine       INTEGER NOT NULL DEFAULT 1, -- drives the batch+expiry rule on receive
  default_tax_pct   REAL NOT NULL DEFAULT 0,
  default_schedule  TEXT NOT NULL DEFAULT 'OTC',
  sort_order        INTEGER NOT NULL DEFAULT 0,
  is_active         INTEGER NOT NULL DEFAULT 1
);

-- Managed base-unit list. The unit label is printed on every receipt and in
-- every rate ("Rs 11.07/cap"), so free text yields tab / Tab / tablet / tabs on
-- products that are the same thing. Nothing groups by it, so the label stays
-- denormalised on products.unit; this list only constrains what can be chosen.
CREATE TABLE base_units (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  name       TEXT NOT NULL UNIQUE,   -- tab, cap, bottle, vial, amp, bag, sachet...
  descr      TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  is_active  INTEGER NOT NULL DEFAULT 1
);

-- Managed manufacturer list; "company-wise sale" in Phase 06 depends on this
CREATE TABLE manufacturers (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  name      TEXT NOT NULL UNIQUE,
  contact   TEXT,
  is_active INTEGER NOT NULL DEFAULT 1
);

-- Parked carts: 4-5 customers in parallel, surviving a reload or a power cut
CREATE TABLE held_sales (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  label       TEXT,                        -- customer name or token, shown on the tab
  counter     TEXT,
  user_id     INTEGER REFERENCES users(id),
  cart        TEXT NOT NULL,               -- JSON: cart lines as the POS holds them
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- A memo of the order the order taker wrote in his own book. NOT a purchase order.
CREATE TABLE order_bookings (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  vendor_id      INTEGER NOT NULL REFERENCES vendors(id),
  taker_name     TEXT,
  taker_contact  TEXT,
  booked_on      TEXT NOT NULL,
  expected_on    TEXT,
  notes          TEXT,                     -- free text; the paper book stays authoritative
  status         TEXT NOT NULL DEFAULT 'booked',  -- booked/partial/delivered/cancelled
  user_id        INTEGER REFERENCES users(id),
  created_at     TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Each dosage form suggests its unit, so a product is never saved with the
-- meaningless schema default of 'unit' on a printed receipt.
ALTER TABLE product_types ADD COLUMN default_unit TEXT;
ALTER TABLE products  ADD COLUMN product_type_id  INTEGER REFERENCES product_types(id);
ALTER TABLE products  ADD COLUMN manufacturer_id  INTEGER REFERENCES manufacturers(id);
ALTER TABLE purchases ADD COLUMN order_booking_id INTEGER REFERENCES order_bookings(id);
```

### Phase 02 — departments: prescription in, invoice out

A department is a **customer that gets an invoice**, not a silent internal transfer. Its
invoices are the hospital's expense.

```sql
CREATE TABLE departments (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  code          TEXT NOT NULL UNIQUE,   -- LAB / EMERGENCY / WARD / OT / ADMIN / DIALYSIS
  name          TEXT NOT NULL,
  in_charge     TEXT,                   -- who signs for it (Q13)
  contact       TEXT,
  customer_id   INTEGER REFERENCES patients(id),  -- its customer record, type 'department'
  invoice_basis TEXT NOT NULL DEFAULT 'cost',     -- cost / cost_plus / mrp  (Q12)
  markup_pct    REAL NOT NULL DEFAULT 0,
  is_active     INTEGER NOT NULL DEFAULT 1,
  sort_order    INTEGER NOT NULL DEFAULT 0
);

-- A prescription or demand slip received from a department, typed at the counter.
-- There is deliberately NO link to a lab/reception record: those modules are on hold.
CREATE TABLE department_requests (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  request_no    TEXT NOT NULL UNIQUE,   -- REQ-00001
  department_id INTEGER NOT NULL REFERENCES departments(id),
  patient_name  TEXT,                   -- the department's own patient; free text
  patient_ref   TEXT,                   -- their MR number if the slip carries one
  slip_ref      TEXT,                   -- the paper slip's serial
  prescriber    TEXT,
  requested_on  TEXT NOT NULL,          -- business date
  status        TEXT NOT NULL DEFAULT 'received', -- received/dispensed/short/invoiced/cancelled
  bill_id       INTEGER REFERENCES bills(id),
  notes         TEXT,
  received_by   INTEGER REFERENCES users(id),
  created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE department_request_items (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  request_id    INTEGER NOT NULL REFERENCES department_requests(id),
  product_id    INTEGER REFERENCES products(id),
  label         TEXT,                   -- what the slip said, before it is matched
  qty_requested INTEGER NOT NULL DEFAULT 0,
  qty_dispensed INTEGER NOT NULL DEFAULT 0,
  unit_price    REAL NOT NULL DEFAULT 0,
  line_total    REAL NOT NULL DEFAULT 0,
  is_emergency  INTEGER NOT NULL DEFAULT 0
);

-- THE separation. Every outward movement and every bill answers both questions.
ALTER TABLE stock_movements ADD COLUMN cost_centre   TEXT;   -- where it went
ALTER TABLE stock_movements ADD COLUMN charge_class  TEXT;   -- who paid
ALTER TABLE bills           ADD COLUMN cost_centre   TEXT;
ALTER TABLE bills           ADD COLUMN charge_class  TEXT;
ALTER TABLE bills           ADD COLUMN department_id INTEGER REFERENCES departments(id);

-- one-off backfill so historical margin stays correct
UPDATE stock_movements SET cost_centre = 'COUNTER' WHERE cost_centre IS NULL;
```

`cost_centre` values: `COUNTER` · `DIALYSIS` · `LAB` · `EMERGENCY` · `WARD` · `OT` · `ADMIN`

`charge_class` values: `PAID` · `CARD_100` · `CARD_50` · `CARD_20` · `STAFF` ·
`DIALYSIS_FREE` · `DEPARTMENT` · `CREDIT` · `ZAKAT`

New counter `request_no` → `REQ-00001`. New `bills.bill_type` value: `department-invoice`.
